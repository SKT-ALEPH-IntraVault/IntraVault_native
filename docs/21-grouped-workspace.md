# 관련 기능을 묶은 업무공간과 내부 전환

2026-09-11 후속 사용자 지시: 함께 쓸 화면을 묶고 내부 컴포넌트만 전환한다. 전환에 적절한 애니메이션을 적용하고 내부 로딩 표시는 제거한다. 기존 RULE 원문은 보존하며 이 지시는 이전 UX-08의 진행률 표시와 UX-12의 독립 상세 화면 구현 선택을 개정한다.

## 화면 구성

| 공간 | 내부 보기 | 유지되는 요소 |
|---|---|---|
| 문서 업무공간 | 한눈에 보기 / 문서 자료실 / 즐겨찾기 / 내 접근기록 | 공통 제목·탭·본문 컨테이너 |
| 관리자 관리 현황 | 대시보드 / 감사로그 | 공통 제목·탭·본문 컨테이너 |
| 관리자 구성원과 권한 | 사용자 / 부서 / 권한 관리 | 공통 제목·탭·본문 컨테이너 |
| 관리자 문서 관리 | 전체 문서 / 기밀문서 | 공통 제목·탭·검색 컨트롤 |
| Security Lab | 보안 설정 / 확인 자료 | 공통 제목·탭·본문 컨테이너 |

문서 상세·등록·수정과 사용자 등록·수정은 목록 위 패널에서 열린다. 사용자 저장을 마치면 패널을 닫고 기준 목록을 갱신한다. 문서는 저장 후 상세를 유지한다. 실습용 파일은 업무 데이터와 별도 공간이며 업로드·목록을 한 화면에 유지한다. 부서 관리자는 기존 자기 부서 관리 화면과 정책을 사용한다.

## 구현 방식

- `config/workspace.php`는 화면 묶음과 탭만 정의한다. 기존 경로·서버 인가·컨트롤러는 그대로 사용한다.
- 공통 레이아웃의 `.workspace-hub`와 `.workspace-tabs`는 같은 공간에서 재생성하지 않는다. `#workspace-view` 내부 내용 또는 목록 영역만 교체한다.
- 문서 자료실↔즐겨찾기, 전체 문서↔기밀문서는 검색 요소도 유지하며 서버가 반환한 필터·수량·선택 상태로 동기화한다.
- 주소는 직접 접근과 뒤로/앞으로 가기를 위해 갱신한다. 주소 변경이 전체 페이지 탐색을 의미하지 않는다. 같은 문서 안에서 서버 HTML 응답을 받아 필요한 영역을 반영한다.
- 직접 상세·편집 주소로 방문하면 처음 받은 서버 화면을 바탕으로 목록을 조회해 같은 업무공간과 패널로 구성한다. 이 동안 입력을 시작했거나 다른 탐색이 발생하면 초기 화면 구성 요청이 사용자의 작업을 덮어쓰지 않는다.
- JavaScript 비활성화 시 기존 서버 페이지와 링크·폼이 동작한다. 로그인·로그아웃·다운로드는 기존 브라우저 동작을 유지한다.

## 전환과 대기 처리

- 갱신된 컴포넌트에 180ms의 짧은 투명도·6px 이동 효과를 적용한다. 패널 열기는 기존 180ms 슬라이드 효과를 사용한다. 임의의 대기 시간으로 응답을 늦추지 않는다.
- 브라우저 기본 Web Animations API와 로컬 CSS를 사용한다. 같은 요소의 이전 전환은 취소하며 오래된 응답은 요청 순번으로 제외한다.
- 동작 줄이기를 설정하면 컴포넌트 애니메이션과 탭 전환 효과를 끈다.
- 내부 로딩 바·스피너·업로드 진행률·‘처리 중’ 문구를 제거했다. 응답을 기다리는 동안 기존 화면을 유지하며 내부 로딩 화면으로 바꾸지 않는다.
- 저장 버튼 비활성화와 중복 제출 방지, 접근성용 `aria-busy`는 유지한다. 응답 성공 전에 저장 완료로 표시하지 않는다. 실패 알림과 입력 보존, 응답 유실 후 서버 상태 확인도 유지한다.

## 반례와 수정 기록

1. Blade의 인라인 PHP 선언 뒤에 블록 선언을 추가하자 템플릿 파서가 잘못 묶는 오류가 발견됐다. 선행 선언도 완결된 블록으로 바꾸고 전체 서버 테스트를 재실행해 통과했다.
2. 동작 줄이기 규칙 뒤에 일반 탭 CSS가 배치되면 효과가 다시 켜질 수 있었다. 마지막 우선순위에 규칙을 두고 실제 계산된 전환 시간 0초를 확인했다.
3. 사용자 행의 이름과 사번이 같은 셀에 있어 검사기의 이름 전체 일치 선택이 실패했다. 행과 계정 이메일로 대상을 지정해 저장·복원을 다시 확인했다. 앱의 저장 실패로 분류하지 않는다.
