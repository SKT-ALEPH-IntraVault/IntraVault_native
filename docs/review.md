## 발견·수정 사항
1. 초기 MariaDB 권한 부여가 테이블 생성보다 빨라 실패했다. 합성 훈련 DB를 독립 스키마로 생성하고 읽기 계정을 해당 스키마에 한정했다.
2. Docker 프로세스 환경이 테스트 DB 설정을 덮었다. tests/bootstrap.php에서 명시 설정하고 TestCase에서 허용 DB를 재확인한다. 최초 빈 개발 설치를 복구한 뒤 실제 Fixture를 생성했다.
3. 명령줄 Fixture가 만든 private 디렉터리가 root 소유라 웹 업로드가 실패했다. Docker 시작 및 Fixture 생성에서 웹 사용자 소유권을 보장했다. 실제 40 MiB 업로드로 재검증했다.
4. 비정상 저장 경로가 라이브러리 예외로 500을 반환했다. 경로 탈출 예외를 404로 처리했다. 파일은 어느 경우에도 반환하지 않았다.
5. 모바일 표에서 한글이 한 글자씩 줄바꿈되었다. 표 최소 폭과 가로 스크롤, 버튼 줄바꿈을 개선하고 화면을 다시 확인했다.
6. 반복 A 문자로 만든 경계 Fixture가 finfo에서 application/SIMH-tape-data로 판정되었다. 방어를 완화하지 않고 text/plain으로 확인된 합성 문장 파일로 경계 검사를 수행했다.

## NASA 기준 전후 검토
- 명확성: /admin과 부서관리의 역할 충돌을 별도 경로로 해소.
- 독립 의무: 원문 ID를 보존하고 01에서 .1/.2 검증 단위로 분해.
- 추적성: 원문 89 ID → 실제 코드/테스트/증거 경로를 연결.
- 구현 가능성: Laravel/MariaDB 실행, Migration, HTTP·브라우저 확인.
- 객관적 판정: 200/302/403/419/422, 파일 내용, 스크립트 marker, 쿠키 재사용으로 판정.
- 충돌: V10을 로그인 회전으로 한정해 정지/로그아웃 불변조건 유지.
- 경계: 40 MiB/+1 byte, 직접 공유 해제, 부서 이동, 훈련 root, 단일 flag, OFF 복구.
- 후속 검증: 실제 Vultr·DuckDNS·TLS 및 별도 프로젝트 복원 검증 완료. 실제 NAS 실행은 미검증이다.

## 배포 후 반례 검토
- 게이트웨이만 고정 주소를 지정하면 Docker 자동 주소 할당이 같은 주소를 앱에 줄 수 있었다. network inspect로 앱이 게이트웨이 예정 주소를 사용함을 확인했고 앱/DB/게이트웨이 주소를 모두 지정한 뒤 정상 기동을 확인했다.
- 브라우저 검증 스크립트가 명시적 type=submit 속성을 찾았지만 실제 로그인 버튼은 HTML 기본 submit 동작을 사용했다. 서버에 POST가 없고 Blade 버튼에 해당 속성이 없음을 확인한 뒤 표시 이름 기반 선택자로 검증을 수정했다. 앱 동작을 변경하지 않았다.
- 소스 백업에서 runtime 디렉터리를 제외하더라도 빌드가 가능하도록 Dockerfile에서 의존성 설치 전에 필요한 Laravel 디렉터리를 생성한다. 실제 백업 소스로 새 이미지를 빌드하고 복원 검증했다.
