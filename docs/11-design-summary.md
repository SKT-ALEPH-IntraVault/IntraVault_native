# IntraVault 설계 요약

작성 기준: 2026-09-10 배포 코드와 검증 결과. 원문 요구사항은 [RULE.md](../RULE.md), 후속 사용자 결정은 [decisions.md](decisions.md)를 따른다.

## 1. 목적과 범위

가상의 사내 문서관리 시스템에서 정상적인 권한 통제와 10개 취약점의 차이를 비교하는 실습 플랫폼이다. 실제 회사 자료나 개인정보를 사용하지 않는다.

로그인, 부서 자료실, 검색, 문서 업로드·조회·다운로드·수정·삭제, 직접 공유, 즐겨찾기, 접근기록, 관리자와 Security Lab을 포함한다. 사용자 자가 회원가입은 제공하지 않는다.

## 2. 기술과 배포 구조

| 구성 | 선택 | 역할 |
|---|---|---|
| 애플리케이션 | PHP 8.4 / Laravel 13 / Blade | 화면과 업무 로직을 하나의 앱에서 처리 |
| UI | Bootstrap 5 | 사내 그룹웨어 화면, 로컬 CSS 자산 사용 |
| 데이터베이스 | MariaDB 11.4 | 계정·부서·문서 메타데이터·공유·감사·취약점 설정 |
| 파일 | Docker 전용 파일 볼륨 | 문서 바이너리와 훈련 파일 보관 |
| 외부 인증 | Nginx Basic Auth | Laravel 로그인보다 바깥에서 실습환경 접근 통제 |
| HTTPS | Caddy | 인증서 발급·갱신 및 HTTPS 연결 |
| 실행·이전 | Docker Compose | 프로젝트별 네트워크·볼륨과 재현 가능한 실행 구성 |

요청 경로는 **사용자 → Caddy HTTPS → Nginx 외부 인증 → Laravel → MariaDB/비공개 파일 저장소**다. 앱 내부의 자세한 흐름은 [시스템 구조](02-system-architecture.md)를 참조한다.

현재 Vultr는 새 전용 인스턴스다. 기존 프록시가 없음을 확인한 뒤 Caddy를 추가했다. 외부에는 HTTPS 프록시의 80/443만 게시하고, Laravel과 MariaDB의 포트는 게시하지 않는다. 인증 게이트웨이의 호스트 연결은 loopback 18081이다.

`compose.production.yaml`은 앱·DB·인증 게이트웨이 공통 구성이고, `compose.standalone.yaml`은 Caddy와 내부 주소를 추가한다. 현재 서버에서는 두 파일을 함께 사용한다.

## 3. 로그인과 역할

웹에 접속하면 먼저 브라우저의 외부 인증 창이 나오고, 통과하면 IntraVault 로그인 화면이 나온다. 두 계정은 별개다. 공개 문서에 비밀번호를 넣지 않으며 사용자 PC의 [.setup/vultr-access.md](../.setup/vultr-access.md)에 보관한다.

| 역할 | 허용 범위 |
|---|---|
| system_admin | 모든 계정·부서·문서·권한·감사·Security Lab 관리 |
| department_admin | 자기 부서 구성원 조회 및 자기 부서 문서 관리 |
| employee | 허용된 문서 열람, 자신의 문서 작성·관리 및 공유 |

시스템 관리자 화면은 `/admin`, 부서 관리자 화면은 `/department/manage`다. 메뉴 노출과 별개로 서버에서 권한을 검사한다.

로그인은 이메일과 비밀번호를 사용한다. suspended 계정은 로그인할 수 없고 기존 세션도 차단된다. 계정 정지로 작성 문서와 감사기록이 삭제되지는 않는다.

## 4. 문서 접근 규칙

| 보안등급 | 열람·다운로드 기준 |
|---|---|
| general | 로그인한 사용자 |
| department | 시스템 관리자, 현재 소속 부서 구성원, 업로더 또는 직접 공유받은 사용자 |
| confidential | 시스템 관리자 또는 해당 문서 부서 관리자 |

기밀 정책이 문서 소유와 직접 공유보다 우선한다. 일반 직원에게 기밀문서를 직접 공유해 접근제어를 우회할 수 없다. 직접 공유는 열람·다운로드 권한이며 수정권한을 자동으로 주지 않는다.

부서 이동 후에도 일반·부서 문서의 본인 업로드 관계와 직접 공유 관계는 유지한다. 이전 부서 구성원이라는 이유만으로 받던 접근권한은 해제된다. 기밀문서는 이동 후의 역할·부서로 다시 판단한다.

검색·목록·즐겨찾기와 직접 접근에 같은 접근제어 기준을 사용하고, 상세조회와 다운로드는 각각 인가한다.

## 5. 데이터와 파일

주요 데이터는 users, departments, documents, document_shares, favorites, audit_logs, lab_flags, lab_uploads, sessions에 저장한다. 관계·제약·인덱스는 [DB 설계](03-database.md)에 정리되어 있다.

- 파일 바이너리는 DB에 저장하지 않고 `storage/app/private`에 둔다.
- DB에는 원본명, 저장명, 경로, MIME, 크기, 작성자, 부서와 보안등급을 저장한다.
- 최대 파일 크기는 40 MiB, 즉 41,943,040 bytes다. 요청 본문 한도는 multipart 여유를 포함해 42 MiB다.
- 정상 업로드는 확장자와 MIME을 검사하고, UUID 기반 이름으로 저장한다. 업로드 파일을 서버에서 실행하지 않는다.
- PDF, DOC/DOCX, XLS/XLSX, PPT/PPTX, TXT, ZIP, JPG/JPEG, PNG를 허용한다.
- 감사기록은 사용자·사건·대상·결과·시각을 남긴다.

SQL Injection 훈련 데이터는 별도 `intravault_lab` DB에 두고 검색용 계정에는 SELECT만 부여한다. 실제 앱 DB를 훈련 검색 대상으로 사용하지 않는다.

## 6. 취약점 스위치

| ID | 의도적으로 약화하는 범위 |
|---|---|
| V01 | 문서 상세조회 인가 |
| V02 | 문서 파일 다운로드 인가 |
| V03 | 훈련용 관리자 보고서의 역할 검사 |
| V04 | 즐겨찾기 변경 POST의 CSRF 보호 |
| V05 | 전용 훈련 디렉터리 내부의 경로 제한 |
| V06 | 합성 훈련 DB 검색의 SQL 바인딩 |
| V07 | 문서 설명 출력의 escaping |
| V08 | 훈련 업로드의 파일 종류 검사 |
| V09 | 로그인 반복 시도 제한 |
| V10 | 로그인 시 세션 ID 재생성 |

설정은 DB에 저장하고 모든 사용자에게 적용한다. 최초 설치는 모두 OFF이며, 서버 재시작 후에도 저장된 상태가 유지된다. 한 스위치를 켜도 다른 스위치의 방어가 사라지지 않게 범위를 나눈다.

V05는 실제 호스트 파일로 벗어날 수 없고, V08은 켜져도 파일 실행·크기 제한 해제를 허용하지 않는다. V10을 켜도 로그아웃 무효화와 정지 계정 차단은 유지한다. 웹 UI에는 공격 payload나 단계별 공격 안내를 넣지 않는다.

## 7. 현재 배포와 검증 범위

- 사이트: https://intravault.duckdns.org
- 서버: 158.247.254.98 / Ubuntu 26.04.1 / 프로젝트 경로 `/opt/intravault`
- 초기 배포 시점: 관리자 1명, 관리 부서 1개, 문서 0개, 스위치 10개 OFF. 이후 사용자가 변경할 수 있는 값이다.
- 로컬 기능 검증: 29개 테스트, 619개 assertion 통과.
- 공개 배포 검증: HTTPS·외부 인증·로그인·관리자 페이지·40 MiB 경계·다운로드 일치·Chrome 화면 확인 통과.
- 이전 검증: 별도 프로젝트에 DB·파일·계정·설정을 복원하고 원본과 대조해 통과.

실제 WTR Pro NAS에서의 실행, NAS 회선의 외부 접속과 DNS 전환은 아직 수행하지 않았다. 더미데이터는 후속 승인으로 4개 부서·13개 계정·24개 문서를 반영했다. [더미데이터 안내](12-demo-data.md)를 참조한다.

## 8. NAS 이전 설계

코드, DB, 업로드 파일, APP_KEY와 접속 인증, 인증서 상태를 하나의 이전 백업으로 묶는다. 장비의 Docker 볼륨 디렉터리를 직접 복사하지 않고 DB 논리 백업과 파일 아카이브로 복원한다. 기존 계정과 비밀번호, 문서 권한과 스위치 상태가 유지되는 방식이다.

주소와 외부 포트는 환경변수로 조정한다. 데이터 볼륨은 Windows/Vultr의 절대 경로에 의존하지 않는다. NAS의 기존 프록시·포트·네트워크를 확인한 뒤 연결한다. 자세한 순서는 [Vultr 운영 및 NAS 이전](10-vultr-nas.md)에 있다.

## 2026-09-11 보안 ON/OFF 구조 개정

중앙 Security 서비스와 security_controls 테이블에서 S01~S16을 평가한다. Security Lab은 전체 ON·OFF와 개별 변경을 제공한다. 인증 미들웨어는 S02 OFF에서 세션별 익명 작업 주체를 생성하며, 문서 조회·다운로드·변경·공유 정책은 독립적으로 판정한다. 상세 범위·레거시 전환·유지되는 기능은 [보안 제어 설계](14-security-controls.md), 비교와 복구는 [실습 안내](15-security-controls-practice.md)를 따른다. 이 개정은 로컬 구현과 검증 결과이며 공개 서버 배포 결과가 아니다.
