# 필요한 영역만 갱신하는 업무공간

후속 개정: 화면 묶음·사용자 편집 패널·직접 링크 처리·내부 로딩 제거는 [21-grouped-workspace.md](21-grouped-workspace.md)가 우선한다. 아래 UX-08 진행률과 UX-12 독립 상세 화면은 최초 구현 기록이며, 후속 사용자 지시에 따라 변경됐다.

사용자 요청: 2026-09-11 첨부 구현 프롬프트. 목표는 목록·입력·탐색 맥락을 유지하면서 부분 갱신하는 웹앱이다. 원문 RULE은 보존한다. 요구사항 공학 학습 문서는 작성·검토 방법으로 참고했으며 새로운 필수 RULE로 승격하지 않는다.

## 요구사항과 구현 선택

사용자 확정: 기존 기능·데이터·S01~S16, Blade·Laravel 모놀리식, 업무/실습 공간 구분, 부분 갱신·문서 패널·탐색 이력·오류 복구.

구현 선택: 기존 GET은 Blade HTML, 기존 변경 경로는 동일한 컨트롤러·정책을 실행한다. Vanilla JS가 HTML의 지정 영역을 가져와 바꾸며 별도 REST API나 프론트엔드 서버를 만들지 않는다. 요청에 `X-IntraVault: workspace`가 있으면 성공 리다이렉트만 204와 목적지 헤더로 바꾼다. 클라이언트는 서버 성공 이후 GET으로 표시 상태를 다시 읽는다. JSON은 기존 Laravel 검증 오류에 사용한다.

네이티브 링크·폼은 JavaScript를 사용할 수 없을 때 그대로 동작한다. 로그인·로그아웃·다운로드는 브라우저의 일반 이동을 유지한다. 기존 로컬 글꼴과 Bootstrap 스타일을 유지하며 새 폰트/라이브러리를 추가하지 않는다. 패널 너비·180ms 전환은 구현 선택이고, 성능 목표 수치가 아니다.

## 상태·예외와 반례

- GET: 이전 요청을 취소하고 요청 순번도 검사한다. 마지막 검색/문서 선택 이후 도착한 옛 응답은 표시하지 않는다.
- 탐색 이력에는 URL·목록 맥락·스크롤만 저장한다. 문서 HTML은 저장하지 않고 뒤/앞 이동에서도 서버 판정을 다시 받는다.
- 목록에서 연 패널은 닫을 때 기준 목록 이력으로 돌아간다. 직접 링크는 정상 독립 페이지이며 목록 링크로 돌아간다. 패널 편집 중 미저장 입력은 닫기/이동 전에 확인한다.
- 변경 성공 후 배경 목록을 다시 읽으므로 현재 부서·검색에 해당하지 않는 문서는 억지로 끼워 넣지 않는다. 마지막 행 삭제로 요청 페이지가 범위를 벗어나면 서버가 마지막 유효 페이지로 이동시킨다.
- 네트워크 유실: 해당 폼은 추가 제출을 막고 ‘서버 상태 확인’을 제공한다. 성공 여부가 모호한 상태에서 자동 재전송하지 않는다. 새 문서는 입력 제목으로 다시 찾고, 실습 업로드는 부서 필터를 제거한 목록에서 확인한다. 이전 필터가 저장된 자료를 가리는 경우를 피한다. 다른 수정은 해당 화면을 다시 읽고 사용자가 결과를 확인한다. 재조회도 실패하면 상태 확인 버튼을 다시 제공한다. 서버의 전역 중복 방지 또는 자동 롤백을 보장한다는 의미는 아니다.
- 업로드 전송 100% 뒤에도 ‘서버에서 저장 중’을 표시한다. 실패 중 같은 폼이 유지되는 동안 파일 선택을 보존하지만 새로고침·이동 후 파일 입력 복원은 브라우저가 허용하지 않는다.
- 403/404 재검증 실패 시 기존 상세를 지운다. 로그인 만료 응답은 로그인 페이지로 전환하며 본문에 로그인 HTML을 삽입하지 않는다.
- 계정 상태·권한이 다른 브라우저에서 바뀐 경우 다음 요청에서 재판정한다. 푸시 알림이나 실시간 동기화 기능은 추가하지 않았다.
- S11이 허용한 서버 HTML의 스크립트 의미를 부분 삽입에서도 보존한다. 이미 실행한 스크립트 효과를 ON 전환만으로 되돌릴 수는 없으므로 기존 실습처럼 각 비교 구간을 새로 로드한 문맥에서 검사한다. 이 UI 변경으로 새로운 출력 허용 지점을 만들지 않는다.
- 새 버전 자산 URL이 감지되면 한 번 정상 페이지 이동하여 코드·스타일을 함께 갱신한다. 이는 배포 버전 전환의 예외이며 일상적인 부분 갱신을 전체 이동으로 흉내 낸 것이 아니다.

검토 반례: 전체 이동을 애니메이션으로 감추기, 저장 실패를 성공 버튼으로 표시하기, 응답 순서에 따라 옛 검색으로 돌아가기, 브라우저 이력 캐시로 옛 권한 화면 부활시키기, 업로드 전송 완료를 저장 완료로 오인하기. 각각 요청 종류·실제 저장·지연 응답·권한 재검증·업로드 상태로 판별한다.

## 검증 및 실행

검증 환경은 기존 업무 preview/공개 서버와 다른 `intravault-security-tests`, `http://localhost:18082`이다. 기존 테스트 계정 파일은 `.setup/security-check-access.json`을 읽고 보고서에 비밀번호를 출력하지 않는다.

```powershell
docker compose -p intravault-security-tests -f compose.yaml -f compose.security-tests.yaml exec -T app php artisan test --compact
node scripts/workspace-browser.cjs
node scripts/workspace-resilience.cjs
node scripts/workspace-edges.cjs
```

브라우저 검증은 기존 격리 테스트 Fixture가 있어야 하며 테스트 파일 안의 `base`를 공개 서버로 바꾸어 실행하지 않는다. 기존 Chrome 경로가 다르면 CHROME_PATH를 사용한다. 실행 결과·남은 자료는 각 증거 JSON을 확인한다.

검증 기록:

- 최종 전체 서버 테스트 **46개 / 1012 assertions 통과**. [JUnit 원본](evidence/workspace-phpunit.xml). 기존 42개와 신규 WorkspaceTransportTest 4개를 포함한다. 신규 검사는 204 성공 전달과 실제 저장 관계, 422/403 실패 유지, S09 ON–OFF–ON, 범위 초과 페이지를 다룬다.
- [업무 흐름 12개](evidence/workspace-browser.json): 실제 요청·저장 후 UI·탐색 이력·노드 유지 확인. 일반 업무 흐름에서 전체 문서 탐색 요청 0회를 확인했다.
- [응답 유실·경쟁·권한/세션·S11 등 11개](evidence/workspace-resilience.json), 별도 임시 문서 정리 결과.
- [추가 경계 5개](evidence/workspace-edges.json): 실제 검색 검증 오류, 스크롤 복원, 미저장 뒤로가기 취소, 자산 버전 전환, JavaScript 비활성화 경로.
- [실제 상세 패널](evidence/workspace-drawer.png), [모바일 자료실](evidence/workspace-mobile.png), [모바일 패널](evidence/workspace-mobile-drawer.png).
- 테스트 도중 로그인 후 복귀 목적지를 루트로 고정했던 정리 도구가 실패했다. 실제 목적지가 달라질 수 있도록 수정했고, 테스트 계정이 만든 정확한 임시 자료를 정리했다.
- 최종 반복 검사에서 패널의 성공 알림이 공유 해제 버튼을 가리는 반례를 발견했다. 알림을 패널 안의 별도 공간으로 옮긴 뒤 같은 흐름을 통과했다.
- 이 로컬 구현 기록 당시 사용자 사용성 평가·NAS에서의 실행·공개 서버 배포·다른 브라우저 엔진 검증은 미실행이었다. 이후 사용자 요청으로 진행한 공개 배포와 실제 HTTPS 결과는 [배포 기록](20-workspace-release.md)에 별도로 정리했다.

### 검증 데이터 정리

업무 흐름 테스트는 임시 문서를 UI로 삭제한다. resilience 테스트는 생성한 문서 URL을 기록하고 종료 시 삭제 및 보안 전체 ON을 확인한다. 별도 실습 업로드에는 삭제 UI가 없으므로 보고서의 practiceUpload에 실행별 파일명을 남긴다.

검증 파일 정리는 `scripts/workspace-cleanup.php`를 사용한다. 이 도구는 SECURITY_TEST_ENV=1과 테스트 관리자 계정을 검사하며, 지정한 13자리 실행 번호의 테스트 제목·파일명만 삭제한다. core-fixtures는 같은 테스트 계정의 workspace.txt 첨부와 UI-실행번호 제목 형식을 모두 만족하는 문서만 정리한다. 공개 서버용 정리 도구가 아니다. 감사로그를 삭제해 초기 수량에 맞추지 않는다.

최종 실행 후 임시 문서와 실습 업로드를 정리했고 테스트 환경의 보안 16개 ON을 확인했다. 계정·원래 문서·공유·파일 데이터와 공개 서버에는 정리 도구를 적용하지 않았다.

## 되돌리기

이 변경에는 DB 마이그레이션이 없다. 배포 시 필요하다면 이전 앱 버전으로 복구하고 뷰 캐시를 갱신한다. 이때 workspace 자산 참조·HTML 영역·미들웨어 등록을 함께 원래 버전으로 돌린다. DB·파일 볼륨을 초기화하지 않는다. 부분 갱신 도입 후 사용자가 저장한 문서·공유·계정 상태는 코드 복구로 되돌아가지 않는다.
