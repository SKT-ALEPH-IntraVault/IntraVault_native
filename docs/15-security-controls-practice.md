# 보안 ON/OFF 실습 순서

> 최신 배포 상태 — 2026-09-11 10:32 KST: 커밋 47f7feb을 Vultr에 배포하고 실제 HTTPS 검증을 완료했다. 보안 16개 모두 ON이며 기존 계정·문서·파일을 보존했다. 아래의 미배포/로컬 검증 문장은 배포 전 작성 기록이다. [배포 및 백업 기록](16-release-20260911.md).

이 안내는 2026-09-11 S01~S16 제어가 구현된 버전 기준이다. 이전 V01~V10 절차와 스위치 방향이 반대다. 공개 Vultr 서버에 새 버전을 배포하기 전에는 해당 서버의 기존 UI에 그대로 적용하지 않는다.

## 시작

1. 관리자용 브라우저 A와 직원용 브라우저 B를 분리한다.
2. /admin/security-lab에서 전체 보안 ON을 선택한다. 이전 V 안내가 없어지고 16개가 모두 ON인지 확인한다.
3. 기본 계정·문서·공유 상태는 docs/12-demo-data.md와 docs/13-demo-accounts.md를 사용한다.
4. 아래 항목을 하나씩 ON → OFF → ON으로 비교한다. 다른 항목은 ON으로 유지한다.
5. 상태를 바꾼 사실과 실제 요청 결과를 따로 기록한다.

## 입력 예제와 요청 조건

- 실제 문서 ID는 제목으로 먼저 확인한다. 초기 배포의 HR-05는 7번이지만 재생성한 테스트 DB에서는 달라질 수 있다.
- S09: 본문 _token과 토큰 헤더를 제거하고 Sec-Fetch-Site를 cross-site로 고정한다. 외부 인증과 유효한 실습 세션은 유지한다. 브라우저 콘솔의 same-origin 요청은 같은 비교가 아니다. 수동 Cookie 재전송은 서버 방어 비교이며 실제 외부 사이트 폼의 종단 간 성공과 구분한다.
- S10: tests/Feature/SecurityControlsTest.php의 test_app_search_output_upload_and_path_controls에서 실제 문서 검색 입력을 확인한다. 이전 V06 입력과 SQL 괄호 구조가 다르므로 같은 문자열이 모든 경로에 통한다고 가정하지 않는다.
- S11: scripts/security-controls-browser.cjs의 무해한 마커 예제를 사용한다. 다른 브라우저에서 window.__control_marker 값을 읽어 실행을 확인한다. 값은 1611이다. ON 복구 후 페이지를 새로 로드하고, 저장한 설명 또는 임시 문서를 제거한다.
- S12: 실행 코드를 넣지 않은 HTML 문서를 사용한다. 저장 성공은 서버 실행 성공이 아니다. 이미 저장한 훈련 업로드는 OFF/ON 변경으로 삭제되지 않으며 현재 삭제 UI도 없다.
- S13: 문서 다운로드의 path 매개변수는 파일 저장소 기준 상대경로다. 예: training-files/restricted/marker.txt. S06이 ON이면 먼저 해당 문서의 정상 다운로드 권한이 필요하다. 최종 저장소 바깥 경로는 S13 OFF에서도 거부된다.
- S14: 이 앱은 제한 시 폼 오류와 리다이렉트로 응답한다. 429만 찾지 말고 제한 메시지와 login.throttled를 확인한다.
- S15: 자동 쿠키 갱신과 자동 리다이렉트를 끈 요청 도구에서 로그인 전 쿠키를 그대로 재사용한다. 로그인 후 쿠키로 바뀌면 비교가 무효다. 로그아웃 후에는 이전 로그인 쿠키가 거부되어야 한다.

## 전체 OFF 기능 점검

1. 관리자 A에서 전체 보안 OFF를 선택한다.
2. 일반 직원 또는 익명 브라우저 B에서 문서 등록·수정·공유·즐겨찾기·다운로드를 수행한다.
3. 다른 브라우저 C에서 같은 문서에 접근한다. 브라우저별 즐겨찾기는 별도로 저장되는지 확인한다.
4. 문서·부서·역할·등급 값이 실제로 저장되는지 확인한다. 접근 차단이 없다는 것과 데이터가 사라지는 것은 다르다.
5. 임시 문서만 삭제하고, 관리자 A 또는 복구 CLI로 전체 보안 ON을 적용한다.
6. 익명 요청·타부서 기밀 요청·관리자 페이지 요청이 다시 차단되는지 확인한다.
7. 변경한 사용자 상태·부서·역할·공유·즐겨찾기를 실습 전 상태로 복구한다. 로그와 익명 계정이 자동 삭제되었다고 기록하지 않는다.

S04가 OFF이면 일반 사용자도 Security Lab 설정을 바꿀 수 있다. 혼자 실습하거나 다른 참가자와 변경 시점을 맞추며, 실습 중 다른 사람이 설정을 바꾸면 해당 비교를 다시 수행한다.
