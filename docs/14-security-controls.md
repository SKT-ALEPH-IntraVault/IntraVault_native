# 보안 ON/OFF 제어 개정

> 최신 배포 상태 — 2026-09-11 10:32 KST: 커밋 47f7feb을 Vultr에 배포하고 실제 HTTPS 검증을 완료했다. 보안 16개 모두 ON이며 기존 계정·문서·파일을 보존했다. 아래의 미배포/로컬 검증 문장은 배포 전 작성 기록이다. [배포 및 백업 기록](16-release-20260911.md).

2026-09-11 사용자 승인: 업무 기능을 유지하고 보안 기능별 ON/OFF와 전체 ON·전체 OFF·사용자 지정을 제공한다. 기존 RULE 원문은 보존하며 이 후속 지시가 보안 설정의 최신 기준이다.

## 설정 의미와 현재 적용 상태

- **보안 ON:** 해당 방어 적용.
- **보안 OFF:** 해당 방어 해제.
- 경로: /admin/security-lab.
- 적용 범위: 애플리케이션 전체 사용자. DB에 저장하므로 로그아웃·재시작으로 초기화되지 않는다.
- 새 설정 테이블은 기본 ON이다. 이번 변경으로 기존 사용자의 비밀번호·문서·공유를 초기화하지 않는다.
- 변경 코드는 로컬 프로젝트에 구현했다. 이번 작업에서 Vultr 서버에 전송하거나 배포하지 않았다. 공개 서버의 실제 배포 상태는 별도로 확인하고 로컬 새 화면과 구분한다.
- 전체 OFF는 아래 16개 보안 제어의 OFF를 뜻한다. 운영체제·프록시·프레임워크를 포함한 모든 보안 장치가 사라진다는 뜻은 아니다.

## 제어 목록

| ID | 보안 기능 | ON | OFF |
|---|---|---|---|
| S01 | 로그인 검증 | 비밀번호 확인 | 존재하는 일반 계정의 비밀번호 확인 생략 |
| S02 | 로그인 필수 | 로그인 전 업무 화면 차단 | 브라우저 세션별 익명 실습 사용자 제공 |
| S03 | 계정 상태 검사 | 정지 계정 로그인·기존 요청 차단 | 계정 정지 상태에 의한 차단 생략 |
| S04 | 역할 검사 | 관리자·부서 관리 역할 검사 | 관리자 업무와 부서 관리의 역할 제한 해제 |
| S05 | 문서 조회 권한 | 소유·소속·등급·공유별 목록/검색/상세 제한 | 전체 문서 조회, 접근 가능한 문서의 즐겨찾기 제한도 해제 |
| S06 | 다운로드 권한 | 문서 접근권한과 훈련 업로드 소유자 확인 | 상세와 독립적으로 다운로드 권한 생략 |
| S07 | 문서 변경 권한 | 소유·부서·역할에 따른 등록/수정/삭제 | 타인·타부서 문서 변경, 직원의 기밀 등록 허용 |
| S08 | 공유 정책 | 공유 관리 권한·기밀 제한 적용 | 기밀 공유와 타인 문서의 공유 관리 허용 |
| S09 | CSRF 방어 | 웹 상태 변경 요청의 요청 위조 검증 | 즐겨찾기뿐 아니라 웹 전체 상태 변경 요청에서 생략 |
| S10 | 검색 입력 보호 | 문서·훈련 검색의 파라미터 바인딩 | 실제 문서 검색과 훈련 검색에서 입력을 SQL에 결합 |
| S11 | 출력 보호 | 문서 제목·파일명·상세 설명 escaping | 지정 문서 출력 위치의 escaping 생략 |
| S12 | 업로드 유형 검사 | 문서·훈련 업로드의 확장자·MIME 검사 | 두 업로드 경로에서 유형 검사 생략 |
| S13 | 다운로드 경로 검사 | 지정 파일 및 훈련 공개 경로 사용 | 앱 파일 저장소 안의 대체 상대경로와 훈련 제한 경로 허용 |
| S14 | 로그인 시도 제한 | 이메일+IP별 5회/60초 제한 | 해당 제한 분기 생략 |
| S15 | 세션 회전 | 로그인 시 세션 ID 회전 | 로그인 전 세션 ID 유지 |
| S16 | 감사로그 조회 권한 | 전체 로그는 관리자, 개인 기록은 본인 | 전체 로그 및 개인 기록 경로에서 다른 사용자 기록 조회 허용 |

문서 조회·다운로드·변경·공유는 서로 독립적인 정책을 사용한다. 예를 들어 S05만 OFF여도 S06 ON이면 권한 없는 파일 다운로드는 차단된다. S07만 OFF여도 S08 ON이면 기밀 공유는 차단된다. S04만 OFF여도 S16 ON이면 일반 사용자의 전체 감사로그 접근은 차단된다.

## 유지되는 기능과 경계

로그인 화면, 로그아웃, 계정·부서·역할·등급 저장, 문서 CRUD·검색·다운로드, 공유, 즐겨찾기, 감사기록, Security Lab은 유지한다. 역할과 등급 정보는 OFF에서 접근 차단 효과가 없어져도 데이터로 남는다.

다음 항목은 이번 스위치 대상이 아니며 전체 OFF에서도 유지된다.

- 필수 값·존재하는 레코드·역할/등급 enum·DB 외래키 등 업무 데이터 형식.
- S01 OFF에도 존재하는 이메일과 비어 있지 않은 비밀번호 입력은 필요하다. 익명 자동 계정은 일반 로그인 대상으로 사용하지 않는다.
- 비밀번호 해시 저장, 비밀번호 변경 시 세션 폐기, 로그아웃에 의한 세션 무효화.
- 마지막 활성 시스템 관리자 보존, 사용자/문서가 들어 있는 부서의 삭제 거부.
- 40 MiB 크기 제한, UUID 저장명, 비공개 파일 저장, attachment·비실행 다운로드.
- 최종 파일 저장소 경계와 심볼릭 링크 탈출 거부. 실제 호스트 파일에 대한 접근을 허용하지 않는다.
- 프록시 외부 인증, HTTPS, 호스트 방화벽, Docker 격리·포트·DB 접속 권한.
- 감사로그 기록 자체. 로그 조회 제한만 S16으로 변경한다.
- S11의 적용 범위는 문서 출력 위치이며 사용자 이름·로그·HTML 입력 속성 등의 모든 출력을 무조건 raw 처리하지 않는다.

LAB_ENABLED=false이면 저장된 값과 관계없이 16개 방어는 ON으로 평가되고 새 UI/CLI 변경은 거부된다.

## 익명 실습 사용자

S02 OFF에서 인증되지 않은 브라우저가 업무 화면을 열면 LAB-GUEST 부서에 익명 사용자 레코드를 만들고, 그 ID를 해당 브라우저의 세션에 보관한다. 작성자·즐겨찾기·로그 관계를 실제 사용자 레코드로 유지하기 위한 처리다.

- 브라우저마다 사용자 ID와 즐겨찾기는 다르다. 익명 계정은 정식 인증 세션으로 로그인되지 않는다.
- 같은 브라우저 세션에서는 익명 사용자를 재사용한다.
- S02를 ON으로 바꾼 뒤 다음 요청부터 로그인 화면으로 이동한다.
- 익명 사용자가 쓴 문서·로그·즐겨찾기와 사용자 레코드는 자동 삭제하지 않는다.
- 익명 사용자들은 같은 LAB-GUEST 부서 소속이므로, 부서 전용 문서는 일반 부서 정책의 영향을 받는다. 브라우저별 파일 격리를 제공한다고 해석하지 않는다.
- 익명 작업을 사용하면 초기 4부서·13계정 수량은 증가한다. 로그아웃하거나 세션을 삭제한 후 새로 접속하면 새 익명 계정이 생길 수 있다.

## 기존 V01~V10과의 전환

이전 V는 ON이 취약 상태였고 새 S는 OFF가 취약 상태다. 숫자나 boolean 값을 그대로 복사하면 안 된다.

| 이전 취약점 | 대응 보안 제어 | 변경점 |
|---|---|---|
| V01 | S05 | 상세뿐 아니라 목록·검색·즐겨찾기까지 적용 |
| V02 | S06 | 문서와 훈련 업로드 다운로드에 적용 |
| V03 | S04 | 합성 보고서뿐 아니라 관리자 업무 기능에 적용 |
| V04 | S09 | 즐겨찾기 POST에서 웹 전체 상태 변경으로 확대 |
| V05 | S13 | 훈련 경로에 더해 실제 문서 다운로드의 대체 경로 지원 |
| V06 | S10 | 훈련 검색에 더해 실제 문서 검색에도 적용 |
| V07 | S11 | 문서 설명에 더해 제목·파일명 출력에도 적용 |
| V08 | S12 | 훈련 업로드에 더해 실제 문서 업로드에도 적용 |
| V09 | S14 | 로그인 시도 제한 |
| V10 | S15 | 로그인 세션 회전 |

마이그레이션은 새 S를 모두 ON으로 생성하고 기존 V 상태는 그대로 보존한다. 이전의 제한된 취약점을 예고 없이 넓히지 않기 위해서다. 기존 V가 ON이면 화면에 활성 ID와 '이전 취약점 설정 사용 중'을 표시한다.

새 S 항목이나 전체 프리셋을 명시적으로 저장하면 기존 V는 모두 OFF로 바뀐다. 선택한 S 변경과 이전 V 해제는 하나의 DB 트랜잭션으로 처리한다. 기존 V 라우트와 코드 경로는 과거 스크립트·검증을 위한 호환 기능으로 남는다. 과거 스크립트를 실행해 V를 다시 켜면 이전 설정 안내가 다시 표시된다.

## 구현 구조

- config/security.php: S01~S16 이름·적용 범위·OFF 설명과 이전 V 대응표.
- security_controls: id, enabled, created_at, updated_at.
- users.is_lab_guest: 자동 익명 계정 식별.
- Security 서비스: 상태 읽기, 단일 변경, 전체 프리셋과 감사기록.
- LabAuthenticate: 로그인 필수/익명 작업 주체 전환.
- Document의 policyVisibleTo와 readableUnderPolicy: S05의 목록 공개와 별개로 다운로드·변경·공유에서 원래 권한을 판정.
- 기존 컨트롤러·미들웨어·Blade에 해당 S 검사를 연결한다.
- security.configure 감사기록에 변경 전 S 상태와 요청한 변경을 남긴다.

## 적용과 복구

공개 서버 배포는 별도 단계다. 대상 환경을 백업한 후 새 코드를 적용하고 다음 명령을 실행한다.

~~~sh
php artisan migrate --force
php artisan optimize:clear
php artisan intravault:security status
~~~

UI에서 전체 ON을 선택하거나 CLI로 다음을 실행하면 정의된 16개 방어를 복구하고 이전 V를 해제한다.

~~~sh
php artisan intravault:security on
~~~

전체 OFF는 명시적인 실습 시작 때만 선택한다. 보안 ON으로 복구해도 이미 변경한 문서·공유·역할·익명 사용자 데이터는 원복되지 않는다. 기존 백업/복원 스크립트는 DB 전체를 내보내므로 새 테이블과 익명 계정도 함께 포함된다.

## 검증

별도 intravault-security-tests Compose 프로젝트와 새 DB·파일·캐시·vendor 볼륨에서 검증했다. 기존 로컬 preview 컨테이너와 볼륨, Vultr 서버는 변경하지 않았다.

- 자동 테스트: 기존 32개 + 신규 8개, 합계 40개 / 954 assertions 통과.
- 신규 검증: 기본값·프리셋·레거시 전환, 각 단일 제어의 문서/관리자 독립성, 비밀번호·정지 계정, 익명 작업, 실제 문서 검색·출력·업로드·경로, 전체 CSRF, 제한·세션 회전, 전체 OFF CRUD.
- 원본 결과: evidence/security-controls-phpunit.xml.
- 브라우저 결과와 스크린샷: evidence/security-controls-browser.json 및 security-controls-on.png / security-controls-off.png. 전체 상태 저장, 익명 기능·즐겨찾기 분리, S11 다른 브라우저 비교, S02 익명 세션 차단의 4개 확인을 통과했다. 종료 시 모두 ON으로 복구하고 임시 문서를 삭제했다.

테스트 실행 예:

~~~sh
docker compose -p intravault-security-tests -f compose.yaml -f compose.security-tests.yaml up -d --no-build
docker compose -p intravault-security-tests -f compose.yaml -f compose.security-tests.yaml exec -T app php artisan test --compact
~~~

compose.security-tests.yaml은 로컬 intravault-app:latest 이미지를 사용한다. 다른 PC에서 해당 이미지가 없으면 먼저 프로젝트 Dockerfile로 이미지를 빌드해야 한다. 테스트 웹 주소는 127.0.0.1:18082이며 공개 서버 주소와 다르다.

브라우저 재검증은 위 별도 스택의 비어 있는 앱 DB를 준비한 뒤 수행한다. Fixture는 기존 사용자가 있으면 중단하고, 테스트 환경 표식이 없으면 중단한다. 임의로 본 서비스 DB를 비우지 않는다. .setup/security-check-access.json에 생성한 테스트 계정을 기록하며 이 파일은 Git 제외다.

~~~powershell
docker compose -p intravault-security-tests -f compose.yaml -f compose.security-tests.yaml exec -T app php artisan migrate --seed --force
docker compose -p intravault-security-tests -f compose.yaml -f compose.security-tests.yaml exec -T --user www-data app php scripts/security-controls-fixture.php
node scripts/security-controls-browser.cjs
~~~

브라우저 검증에는 프로젝트의 Playwright 의존성과 Chrome이 필요하다. Chrome 경로는 CHROME_PATH로 변경할 수 있다. 이미 Fixture를 만든 같은 테스트 환경에서는 마지막 브라우저 명령만 다시 실행한다.
