## 반영 내용

사이드바와 상단을 유지하면서 목록·검색·부서·상세 패널을 갱신한다. 문서 등록·수정·즐겨찾기·공유는 서버 응답을 확인한 뒤 화면에 반영한다. 이력 이동, 미저장 입력 확인, 오류 복구, 모바일 패널을 포함한다. [구현과 요구사항 추적](19-incremental-workspace.md).

기존 Docker Compose와 DB·파일 볼륨을 사용했다. 실행 파일만 정확한 커밋에서 묶어 전송하고 별도 디렉터리에서 이미지를 먼저 빌드했다. 유지보수 상태에서 전체 이전용 백업의 SHA256SUMS를 확인한 뒤 앱 컨테이너만 교체했다. DB 마이그레이션·초기화는 없으며 gateway·Caddy·DB 컨테이너는 재생성하지 않았다.

## 이용 및 복구

이미 열려 있던 탭은 한 번 새로고침하면 새 인터페이스를 사용한다. 새 버전 자산 감지에 따른 정상 새로고침과 로그인·로그아웃·다운로드 등 기본 동작은 일반 목록 부분 갱신과 구분한다.

복구가 필요하면 `/opt/intravault`에서 이전 이미지를 `intravault-prod-app:latest`로 다시 태그하고 동일 Compose 파일로 앱만 교체한 다음 `optimize:clear`, `view:cache`, `up`을 실행한다. 다음 빌드도 이전 소스를 사용해야 한다면 위 백업의 소스를 별도로 확인해 복구한다. DB와 파일 볼륨을 초기화하지 않으며, 배포 후 사용자가 저장한 데이터는 코드 복구만으로 되돌아가지 않는다.

배포 검증 문서·스크린샷의 후속 커밋은 실행 커밋과 별개다. 서버 `.setup/deployed-commit.txt`는 위 실행 커밋을 가리킨다.
