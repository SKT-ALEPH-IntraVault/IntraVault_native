# UI 디자인 원칙과 적용 기록

2026-09-11 사용자 지시: 모던한 인상을 만들고, 딱딱하고 각진 UI/UX를 지양하며 기존 프로젝트 원칙을 지킨다.

## 시각적 기준

- 사이드바·패널·부서 카드는 18~28px의 둥근 형태를 사용한다. 버튼과 상태 배지는 알약 형태로 통일한다.
- 밝은 회청색 바탕과 흰색 화면 영역, 파란색 주요 동작을 사용한다. 실습용 파일은 기존의 따뜻한 색상과 별도 공간 표시를 유지한다.
- 두꺼운 테두리 대신 얇은 경계·여백·옅은 그림자로 영역을 구분한다. 목록은 정렬과 표 구조를 유지하여 파일명·부서·등급을 비교할 수 있게 한다.
- 메뉴는 의미를 가진 선형 아이콘과 텍스트를 함께 사용한다. 선택된 부서와 메뉴, 보안 ON/OFF는 색상 외에 텍스트로도 확인할 수 있어야 한다.
- 키보드 초점 표시, 모바일에서 누르기 쉬운 조작부, 동작 줄이기 설정을 유지한다.
- 새 외부 폰트·이미지·UI 라이브러리는 추가하지 않는다. 기존 Bootstrap 5와 로컬 CSS·SVG를 사용한다.

## 기능 원칙

RULE 원문 및 사용자 후속 승인한 S01~S16 정의는 유지한다. 사용자·관리자 공간과 라우트 분리, 문서 접근 정책, 보안 스위치 독립성, 실습 파일과 업무 문서 구분, 부서별 탐색과 뒤로가기 동작을 보존한다. 장식 변경을 이유로 컨트롤러·DB·권한 로직을 바꾸지 않는다.

공격 입력이나 튜토리얼을 웹 UI에 추가하지 않는다. 검색 필터나 UI 동작용 JavaScript를 불필요하게 늘리지 않는다.

## 구현과 검증

공통 레이아웃에서 public/assets/modern.css를 기존 스타일 뒤에 로드한다. 색상·간격·모서리 크기를 공통으로 관리하고, 메뉴 아이콘은 navigation-icon Blade 컴포넌트를 사용한다. 로그인·문서·관리자·실습 화면에 같은 디자인을 적용한다.

- 격리된 로컬 환경에서 로그인과 15개 업무 경로가 정상 응답했고 JavaScript 오류가 없었다.
- 데스크톱과 390/320px 모바일에서 페이지 전체 가로 넘침을 확인했다. 넓은 표는 기존처럼 표 영역 안에서 가로 스크롤한다.
- 부서 클릭 시 검색어 초기화, 문서 상세에서 이전 부서 목록으로 뒤로가기, 동작 줄이기 설정을 확인했다.
- CSS와 공통 메뉴 표현만 변경했으므로 전체 기능 테스트를 불필요하게 반복하지 않았다. 이번 브라우저 확인을 서버 배포 검증으로 표시하지 않는다.
