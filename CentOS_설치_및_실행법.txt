IntraVault Native — CentOS Stream 9 설치 및 실행 안내
=====================================================

적용 대상
- 저장소: SKT-ALEPH-IntraVault/IntraVault_native
- 권장 설치 위치: /opt/intravault
- 기본 포트: 18080/tcp
- 웹 루트: public/

중요
- 이 프로젝트에는 의도적으로 보안 방어를 해제하는 Security Lab이 포함됩니다.
- 실제 개인정보·회사 문서를 넣지 말고 격리된 교육망에서만 사용하세요.
- 외부 인터넷에 18080 포트를 그대로 공개하지 마세요.
- 아래 명령은 CentOS Stream 9 기준입니다. root 명령과 intravault 계정 명령을 구분하세요.


1. 필수 패키지 설치 (root)
---------------------------

dnf install -y dnf-plugins-core
dnf config-manager --set-enabled crb
dnf install -y https://dl.fedoraproject.org/pub/epel/epel-release-latest-9.noarch.rpm
dnf install -y https://rpms.remirepo.net/enterprise/remi-release-9.rpm
dnf module switch-to -y php:remi-8.4/common
dnf install -y php-cli php-common php-mysqlnd php-mbstring php-xml php-curl php-zip php-intl php-gd php-opcache composer mariadb-server git tar unzip curl firewalld

설치 확인:

php -v
composer --version
mariadb --version
php -m

Laravel 13은 PHP 8.3 이상과 Ctype, cURL, DOM, Fileinfo, Filter, Hash,
Mbstring, OpenSSL, PCRE, PDO, Session, Tokenizer, XML 확장이 필요합니다.


2. MariaDB와 방화벽 서비스 시작 (root)
---------------------------------------

systemctl enable --now mariadb
systemctl enable --now firewalld
systemctl is-active mariadb
systemctl is-active firewalld

선택 사항이지만 새 MariaDB 서버라면 기본 보안 설정을 먼저 수행합니다.

mariadb-secure-installation


3. 프로젝트를 CentOS로 복사
----------------------------

방법 A — Git으로 직접 받기:

cd /opt
git clone https://github.com/SKT-ALEPH-IntraVault/IntraVault_native.git intravault

방법 B — 다른 PC에서 파일로 복사하기:

원본 PC의 IntraVault_native 저장소 루트에서 .git, .env, vendor를 제외해 묶습니다.

tar --exclude=.git --exclude=.env --exclude=vendor -czf intravault-native.tar.gz .
scp intravault-native.tar.gz root@CENTOS_IP:/root/

CentOS에서 풉니다.

mkdir -p /opt/intravault
tar -xzf /root/intravault-native.tar.gz -C /opt/intravault

최종적으로 /opt/intravault/artisan, /opt/intravault/composer.json,
/opt/intravault/native 디렉터리가 보여야 합니다.


4. 서비스 계정과 파일 권한 준비 (root)
---------------------------------------

id intravault >/dev/null 2>&1 || useradd --system --home-dir /opt/intravault --shell /sbin/nologin intravault
cd /opt/intravault
mkdir -p vendor storage/app/private storage/framework/sessions storage/framework/views storage/framework/cache/data storage/logs bootstrap/cache
chown -R root:root /opt/intravault
chown -R intravault:intravault vendor storage bootstrap/cache
chmod 755 /opt/intravault

애플리케이션 코드는 root 소유 읽기 전용으로 두고, 실행 계정에는 vendor,
storage, bootstrap/cache만 쓰기 권한을 줍니다.


5. 환경변수와 데이터베이스 설정 (root)
----------------------------------------

cd /opt/intravault
cp -n .env.example .env
nano .env

반드시 변경할 값:

APP_URL=http://CENTOS_IP:18080
DB_PASSWORD=서로_다른_긴_임의_비밀번호_1
LAB_DB_PASSWORD=서로_다른_긴_임의_비밀번호_2

원격 PC에서 접속할 때만 다음 값도 변경합니다.

INTRAVAULT_BIND=0.0.0.0

APP_ENV=local, APP_DEBUG=false는 그대로 둡니다. 현재 애플리케이션은
APP_ENV=production일 때 HTTPS를 강제하므로, HTTPS 리버스 프록시 없이 production으로
바꾸면 HTTP 접속이 정상 동작하지 않습니다.

이어서 DB 생성 스크립트의 비밀번호도 .env와 똑같이 바꿉니다.

nano native/database.sql

replace-with-random-password  -> DB_PASSWORD 값
replace-with-reader-password  -> LAB_DB_PASSWORD 값

작은따옴표는 지우지 않습니다. 설정 파일 권한을 제한합니다.

chown intravault:intravault .env
chmod 600 .env
chown root:root native/database.sql
chmod 600 native/database.sql


6. 데이터베이스와 계정 생성 — 최초 한 번만 (root)
---------------------------------------------------

cd /opt/intravault
mariadb --protocol=socket < native/database.sql

확인:

mariadb --protocol=socket -e "SHOW DATABASES LIKE 'intravault_native%';"

다음 두 DB가 보여야 합니다.
- intravault_native
- intravault_native_lab

native/database.sql은 재실행용 스크립트가 아닙니다. 이미 DB와 계정이 있으면
다시 실행하지 마세요.


7. PHP 라이브러리 설치와 앱 초기화 (root에서 runuser 사용)
------------------------------------------------------------

cd /opt/intravault
runuser -u intravault -- bash native/setup.sh

setup.sh가 수행하는 작업:
- PHP 버전과 필수 확장 확인
- Composer 운영 의존성 설치
- native 환경설정 검증
- APP_KEY가 없을 때만 생성
- Migration과 Seeder 실행
- 현재 앱 상태 출력

오류 없이 끝난 뒤 최초 관리자 계정을 만듭니다.

runuser -u intravault -- php artisan intravault:create-admin

비밀번호는 12자 이상이어야 합니다. 입력 중 화면에 표시되지 않을 수 있습니다.


8. 우선 터미널에서 실행해 확인
--------------------------------

로컬 CentOS에서만 확인:

cd /opt/intravault
runuser -u intravault -- bash native/start.sh

다른 PC에서 접속 확인:

cd /opt/intravault
runuser -u intravault -- env INTRAVAULT_BIND=0.0.0.0 bash native/start.sh

브라우저:
http://CENTOS_IP:18080

서버 자체 확인:

curl -I http://127.0.0.1:18080/up

종료:
Ctrl+C


9. systemd 서비스 등록 (상시 실행할 때, root)
------------------------------------------------

아래 파일을 만듭니다.

nano /etc/systemd/system/intravault.service

내용:

[Unit]
Description=IntraVault Native Laravel Service
After=network-online.target mariadb.service
Wants=network-online.target
Requires=mariadb.service

[Service]
Type=simple
User=intravault
Group=intravault
WorkingDirectory=/opt/intravault
Environment=INTRAVAULT_BIND=0.0.0.0
Environment=INTRAVAULT_PORT=18080
ExecStart=/usr/bin/bash /opt/intravault/native/start.sh
Restart=on-failure
RestartSec=5
UMask=0027
NoNewPrivileges=true
PrivateTmp=true
ProtectHome=true
ProtectSystem=full
ReadWritePaths=/opt/intravault/storage /opt/intravault/bootstrap/cache

[Install]
WantedBy=multi-user.target

등록 및 시작:

systemctl daemon-reload
systemctl enable --now intravault
systemctl status intravault --no-pager

참고: 이 systemd 예시는 격리된 교육망에서 Laravel 내장 서버를 간단히 유지하기 위한
구성입니다. 실제 운영 공개 서비스는 Nginx 또는 Apache가 public/만 웹 루트로 제공하고
PHP-FPM을 사용해야 합니다.


10. 방화벽과 포트 확인 (root)
--------------------------------

원격 PC 접속이 필요하고 CentOS가 신뢰할 수 있는 사설망에 있을 때만 포트를 엽니다.

firewall-cmd --permanent --add-port=18080/tcp
firewall-cmd --reload
firewall-cmd --list-ports

더 안전하게 하려면 전체 공개 대신 관리 PC 또는 교육망 CIDR만 허용하는 rich rule을
사용하세요. 공용 클라우드 보안그룹이 있다면 그쪽에서도 18080/tcp를 교육망 IP로만
제한해야 합니다.

리스닝 확인:

ss -ltnp | grep ':18080'
curl -I http://127.0.0.1:18080/up


11. 로그 확인
-------------

서비스 로그 실시간 확인:

journalctl -u intravault -f

최근 100줄:

journalctl -u intravault -n 100 --no-pager

Laravel 로그:

tail -f /opt/intravault/storage/logs/laravel.log

MariaDB 로그:

journalctl -u mariadb -n 100 --no-pager


12. 종료, 시작, 재시작
----------------------

systemctl stop intravault
systemctl start intravault
systemctl restart intravault
systemctl status intravault --no-pager

부팅 자동 시작 해제:

systemctl disable --now intravault


13. 코드 갱신
-------------

서비스를 정지하고 백업한 뒤 새 파일로 교체합니다. .env, storage, DB는 보존합니다.

systemctl stop intravault
cd /opt/intravault
cp .env /root/intravault.env.backup
tar -czf /root/intravault-storage-backup.tar.gz storage
mariadb-dump --protocol=socket intravault_native > /root/intravault-db-backup.sql

새 코드 복사 후:

chown -R root:root /opt/intravault
mkdir -p vendor storage/app/private storage/framework/sessions storage/framework/views storage/framework/cache/data storage/logs bootstrap/cache
chown -R intravault:intravault vendor storage bootstrap/cache
chown intravault:intravault .env
chmod 600 .env
chown root:root native/database.sql
chmod 600 native/database.sql
runuser -u intravault -- bash native/setup.sh
systemctl start intravault


14. 자주 생기는 문제
---------------------

- 500 오류: journalctl -u intravault -n 100 및 storage/logs/laravel.log 확인
- DB 연결 실패: systemctl status mariadb, .env의 DB_* 값, 비밀번호 일치 여부 확인
- 권한 오류: storage와 bootstrap/cache가 intravault 계정 소유인지 확인
- 외부 접속 불가: INTRAVAULT_BIND=0.0.0.0, firewalld, VM 네트워크, 보안그룹 확인
- 업로드 용량 오류: PHP_INI_SCAN_DIR에 /opt/intravault/native가 포함되는지 확인
- 설정 변경 미반영: runuser -u intravault -- php artisan optimize:clear 후 서비스 재시작


15. 최소 정상 확인 순서
----------------------

systemctl is-active mariadb
systemctl is-active intravault
curl -I http://127.0.0.1:18080/up
cd /opt/intravault
runuser -u intravault -- php artisan intravault:check

브라우저에서 관리자 로그인, 문서 목록, 훈련자료실, Security Lab 화면을 차례로
확인합니다. 실제 민감정보 대신 합성 훈련자료만 사용하세요.
